## 게임·모드가 갱신되면 (2026-11-20에 한 순서)

게임을 끈 상태에서 한다(빌드는 실행 중이면 멈춘다). 먼저 정션을 확인한다.

1. 무엇이 바뀌었는지: 새 pak을 `tools/Export-PakText.ps1`로 임시 폴더에 풀어 `data/file-index.csv`(모드는 `data/mods/<id>/file-index.csv`)의 `Sha1`과 비교하고, 출력 모드 파일 목록과 겹치는지 본다. 기존 프로젝트를 임시 `--settings`(다른 `outputModDir`)로 빌드하면 "원본이 바뀜" 수를 실제 출력을 건드리지 않고 셀 수 있다.
2. 게임이 바뀌었으면: `_work/vanilla` → `vanilla.old-<날짜>`, 바닐라 다시 분석(`CLAUDE.md` "바닐라 전체 재생성"), `Build-DisplayNames`, `New-SchemaDoc` → `Test-Coverage`(`keys-missing=0`), `New-EditableDoc`.
3. 모드: 옛 추출본 이름 바꾸기 → 바뀐 모드만 모드 분석(Fusion은 `-FallbackWorkDir @('_work\mods\2905667604','_work\vanilla')`) → 네 모드 모두 `Compare-ModToVanilla` → `Get-ModSummary` → `New-ModDoc`. `mods.psv` 갱신일·크기와 `notes.md`를 고친다.
4. `vision-preset --variant wot --classes --project editor/projects/월드워-차종.json --force` → `faction-preset --army ger --base editor/projects/월드워-차종.json --project editor/projects/강화-독일.json --force` → `build --project editor/projects/강화-독일.json`.
5. `spawn-menu build` → `l10n extract`(L1: 지워진 `cheat.po`·`mission/.po`는 `git restore`) → 새 항목 채우기 → `l10n check` → `l10n build` → `spawn-menu build`.
6. 테스트, `real`, `real-spawn`.

`.po`를 스크립트로 고칠 때는 항목 사이 빈 줄을 지키고(2026-11-20에 한 번 사라져 되살렸다), PowerShell에서 `[IO.File]`을 쓰면 `[Environment]::CurrentDirectory`가 저장소 루트인지 본다.
